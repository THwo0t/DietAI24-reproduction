# P capacity-v4 preparation protocol

This entry prepares private development data and identity-only independent
acceptance proposals. It performs no inference, scoring, network download,
acceptance designation or validation target/image inspection. All old sources,
cohorts, folds and O results remain unchanged. The public entry has no arguments
or source overrides and requires an isolated network namespace.

The first read is the fixed preparation review gate. It must name scope
`P_capacity_v4_preparation`, status `approved_or_fixed`, integer unresolved P1/P2
count zero, the exact preparation source/old-vector-asset inventory, the review
text digest, and all five registered mechanical receipts. Every source digest
and review digest is verified before invoking the source assembly, opening old
development/support labels or interpreting candidate totals. A missing or
unapproved gate refuses preparation. This document does not supply an approval.

R-PC6-1 binds the current transitive project implementation, independently of
historical implementation hashes retained inside the immutable receipts. The
static preparation inventory includes the source helpers' module-level import
closure and the local imports reached by catalogue validation and fixed source
assembly. It also includes the schema/namespace supplier and its import-time
project dependencies. No unused lazy provider/task-gate execution is enabled.

The explicit additional current source pins are `round11/service_p.py`,
`round11/asa_source_capture.py`, `round11/legacy_input_identity.py`,
`round11/local_content_inventory.py`, `round11/local_input_inventory.py`,
`round11/n5_potential_identity.py`, `round4/src/artifacts.py`,
`round7/src/historical_m.py`, `round7/src/runtime_m.py`,
`round7/src/service_m.py`, `src/cohorts_v2.py`, `src/opt_pipeline.py` and
`src/opt_provider.py`. These paths are relative to the MAE-v2 source root.
They are authenticated before source assembly and remain in the bound reader's
used set through final post-publication revalidation. A changed or missing
implementation refuses preparation; historical receipt hashes are neither
rewritten nor treated as substitutes for these current review pins.

The source assembly authenticates the five existing receipts, unchanged original
controls, fixed N5/development/training/caller readers and held ASA identity
bindings. It does not recapture the mechanical inventory, reopen an O scientific
run or parse historical result payloads. All bound readers, source pins and
controls are revalidated before and after preparation. Source-scope v3 retains
all missing-source components in quarantine, all protected roles and every
unassigned local byte/RGB digest; global source and actual-exposure completeness
remain false.

Development uses all 84 N5 core rows and all 230 accepted historical support
observations. Capacity-v4 folds group complete associations together; all retained
ambiguous components share one uncertainty-containment unit, without asserting
physical plate identity. The helper refuses fewer than five units. Original
core and support source bindings remain in the private closure proof. Support
reuse is explicitly historical development, not fresh or independent evidence.

ASA retains all 99 original core records and references, adds all admitted legal
extras outside missing/validation components, and adds 20 safe broader-frame
components in the registered order. ASA source workbook and weight fields are
interpreted only for the bounded permitted code set. Before component selection,
the new catalogue includes every distinct legal option from every admitted safe
broader code and core-extra code, including codes outside the selected twenty
components. Existing ASA option entries, IDs and order remain an exact prefix;
new distinct legal entries append deterministically. Newly admitted codes receive
their complete legal lists. All other catalogue fields, food descriptions,
densities and standard options remain exact. Every prepared ASA target mass must
match a legal gram value in its code's resulting complete catalogue. The new
catalogue is private and separate; no old catalogue is overwritten.

New ASA records use `asa24-<eight-digit-code>-extra-<source-row-digest>` so code
identity is explicit for later isolated adapter checks. Their separately held
size label is `all_legal`. Old core size bins and source IDs are preserved. All
runtime image paths use neutral digests. Original group/fold/source bindings and
new association/fold/stratum bindings remain separate in the closure proof.

The independent N5 proposal retains the 102 unlinked old seven-field validation
rows and selects up to 98 source-valid official-RGB identities from the at-most
137 unblocked full-raw frame. All old reserved associations remain blocked.
Protected raw rows are skipped before converting any of their five targets.
Unblocked targets are checked only for finite/nonnegative values, positive mass
and present nutrition; their values are never exported. Capacity-v4 fixed-seed
component ordering and round-robin dish selection determine the proposal, with
explicit fixed-order shortfalls. Official URLs and nominal body bytes are only
metadata; content digests remain unknown until an independently authorized
future download. Limits are 5 MiB per response, three attempts per fixed URL and
200 MiB total future response bodies including retries. This entry downloads
nothing and does not designate acceptance. The separate ASA proposal retains
75 old identities and proposes three replacement identities when feasible;
proposal portion target values are not exported.

Only authenticated old development and accepted support labels supply N5
supervision. Original ASA labels remain exact; new ASA development targets are
mechanical legal-source grams times the unchanged public code density. No
validation labels, protected validation images, ingredient truth or historical
predictions are consumed. Blind image copies verify source-byte hashes and a
5 MiB bound, using component-wise no-follow access or the exact authenticated
ASA ZIP member. No visual interpretation occurs. Links, missing bodies, changed
sources, duplicate identities and cross-fold association units cause refusal;
there is no reroll or silent substitution.

The producer writes the seven context role files, copied neutral development
images, the new catalogue, a source-closure/proposal proof and common bindings.
Fallback medians exclude the query fold and group and include explicit training
and held-out IDs/groups. Inference calibration is disabled with identity
multipliers; supervised postprocessing belongs to a separately reviewed scoring
phase. The embedding import manifest is empty and permits fresh P queries only.
Existing vector files remain in place; the fixed matrix is streamed for a digest
under a 96 MiB bound, never read through the 64 MiB whole-body reader.

Every output file is exclusive `0600` in component-wise no-follow `0700`
preparation directories. Resume compares immutable bytes; it never overwrites a
partial or changed file. Common bindings are published last, followed by a full
source revalidation. A partial publication is preserved for diagnosis and cannot
supply an inference science freeze. The cohort status is
`prepared_development_pending_integrated_review`; a later independent cohort/runtime
review and separately source-bound science freeze are still mandatory. No
runtime review gate or `round11/prepared/freeze.json` is fabricated here.

Private fixture seams accept synthetic readers and small populations solely for
offline tests. The public no-argument entry always uses the fixed source readers,
counts, paths, pins and review requirements above. Tests do not invoke the
production readers or inspect actual research data.
