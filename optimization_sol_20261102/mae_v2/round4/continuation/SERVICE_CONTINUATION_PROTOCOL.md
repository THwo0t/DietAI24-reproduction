# J service continuation — registered before complete base scoring

Date: 3 November 2026. This is one explicit service-policy departure from the
original J protocol, under the existing unlimited paid-development authorization.
It does not replace or edit the original frozen code, protocol, attempts, failed
run or acquisition evidence. No J MAE, partial MAE, calibration or validation
result has been examined to choose this continuation.

## Trigger and preserved work

The 230-image gallery completed. J then stopped because one exact chat payload,
at visual reranking, exhausted three transmissions with `ReadTimeout`. The
coordinator reported 49/84 before stopping; outstanding workers subsequently
left 52 sealed estimation stages, 53 descriptions/embeddings/retrievals and 52
rerank stages. These are resumable stages, not a completed 84-record score.
There is one unfinished rerank stage. Five other payloads encountered transient
errors and ultimately returned successfully. `round4/service_interruption.json`
records safe aggregates and returned token usage; timeout-side usage is unknown.

Do not rerun successfully observed answers, drop a sample, synthesize an old J
completion seal, reset persistent counters, or change the namespace to evade a
limit. Preserve the old source, source bindings, full old stage bytes/seals,
provider log and snapshots of attempt/cache state. The original J remains stopped.

## Sole additional service allowance

Keep the same URL, model, credentials, namespace and exact payload identity.
The namespace remains `external-gallery-r4.1`, including the cache key. Use
600-second read timeout, 30-second connect timeout, and 120-second write/pool
timeouts for this continuation. All other inference parameters and the one
format-repair limit are unchanged. Use at most two workers (default two) to
reduce simultaneous requests; this changes scheduling, not the scientific inputs.

Exactly one payload receives one additional HTTP transmission, giving a
cumulative cap of four. Its private registration must establish the exact hash,
chat role, three recorded `ReadTimeout` failures, persistent count three, no
successful response, and no existing response cache at registration. Match that
hash exactly, preserve prior reservations and record any fourth reservation
durably before sending. If a valid successful cache appears, use it without
another transmission. Every other payload retains its original cumulative cap
of three, including existing counters. New payloads also have cap three.

The extra transmission is a disclosed deviation; it is not described as being
within the old three-attempt rule. Authentication/model failures, integrity
failures or another exhausted limit stop the continuation. No automatic second
extension, new namespace or repeated repair candidate is authorized by this
protocol. The reason for the retry is missing service output, never nutritional
error. Returned token usage and unresolved timeout billing remain explicit.

the complete gallery, training freeze and original scientific sources/query
manifest, original provider logs, and old response/attempt snapshots. It records
the singleton allowance and its evidence before a new call. New protocol and
implementation hashes must be bound before execution as well. No query labels
are a base-inference input.

Create a separate `round4/runs/J_service_continuation` ArtifactStore. Each imported
stage must match its original name and exact inputs, old run binding, external
receipt and response hash, and pass the same raw-output reparse/validator as
before. Validate its request references. Reuse all sealed terminal outcomes,
including structure failures; import cannot choose only favorable outcomes.
Record the exact import provenance and write a new envelope under the new
binding. Copying an old envelope into a different binding is insufficient.

Fresh stages use the original appearance/retrieval/rerank/estimation pipeline and
image guard. The default method configuration is preserved, with a separate
explicit service-continuation override for timeout and the singleton cap-four
exception. Original stage files, logs and cached successful responses remain
unchanged. The shared attempt ledger continues increasing from its old counts;
the old state is retained in the registration snapshot. Reconstruct all 84 final
records from imported/fresh stages and seal only the complete population.

explicit evaluator verifies the complete continuation seal, external-only train
binding, registered service departure, preserved stage provenance and original

monkeypatching them or changing their mathematical behavior.

main denominator and use the same preserved 99 ASA24 records. The registered

`2f921d76f6f08ada8faa87648638fd17c4bff7d78aa0099bacb1318ce81d6e5b`:
raw grid 0.5–2.0 in steps of 0.001, 50% shrinkage, grouped five-fold isolation,
whole-fallback preservation, raw-passed-check protection, one whole-profile
worst/mean-ratio decision and no target-wise mixing. This protocol extends its
artifact entry point only; it does not introduce another calibration candidate.

Bind this protocol, private registration and new implementation alongside the
original pure helper sources. A completed continuation/evaluation verifies

All resulting accuracy figures remain exploratory development results. Formal
